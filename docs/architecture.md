# 架构说明

本文件描述软件的分层与关键设计决策。**不含源代码**，只用结构图与规则说明表达实现思路。

## 1. 进程与分层

```
┌──────────────────────────────────────────────┐
│ 桌面外壳（PySide6 / QtWebEngine）            │
│  · 单窗口，内嵌浏览器                        │
│  · 守护后端进程：启动、健康检查、端口协商     │
│  · 下载处理、热重载、出处校验拦截             │
└───────────────────┬──────────────────────────┘
                    │ 只监听 127.0.0.1
┌───────────────────▼──────────────────────────┐
│ 本地服务（Python 标准库 HTTP，无框架依赖）    │
│  · 静态资源托管（web/）                      │
│  · /api/* 业务接口                            │
│  · /api/workspace-snapshot 工作区读写         │
│  · 模型代理：统一出口、拒绝内网目标            │
└───────────────────┬──────────────────────────┘
                    │
┌───────────────────▼──────────────────────────┐
│ 能力层（纯函数模块，可单独测试）              │
│  · 后期包装：配音 / 字幕 / 混音 / 调色 / 封面 │
│  · 局部重绘（inpainting）                     │
│  · 音效库（sfx）                              │
└──────────────────────────────────────────────┘
```

设计取舍：**外壳只做窗口与进程管理，业务全部在服务端**。这样界面可以在浏览器里独立调试，
服务端也可以脱离 Qt 单独跑；换外壳（Electron、纯浏览器）不影响业务代码。

外壳启动时用 `--port 0` 让操作系统分配端口，而不是固定端口。原因：固定端口在有旧实例
残留时会被 `SO_REUSEADDR` 抢到，请求落到旧进程上，界面看着对、数据却不是这一份。

## 2. 状态存放

- 真源：本地服务的 `/api/workspace-snapshot`，落盘为工程目录下的 `.cache/*.json`。
- 浏览器 `localStorage` 只是镜像，用于首屏快速渲染。
- 因此「换一个目录打开软件 = 一份独立数据」，互不干扰；跨安装搬迁有专门工具（见 `docs/features.md`）。

## 3. 模型配置的四级结构

```
模块 module  ──▶ 服务商 provider ──▶ 模型 model ──▶ 参数 param
  对话               OpenAI             gpt-4.1        temperature
  图片               火山方舟           Seedream       size
  视频               阿里云百炼         wan2.7-video   resolution
                     智谱 · 腾讯混元 · MiniMax · 海螺 …
```

每个参数项都有描述符：键名、显示名、类型（枚举 / 数值 / 布尔 / 文本）、范围、默认值、
是否**真正进请求**。界面只渲染描述符，不认识任何具体服务商。

规模：3 个模块 / 12 家服务商 / 32 个模型 / 99 个参数项，由脚本从注册表生成单一数据源，
界面与迁移逻辑共用这一份数据。

### 参数取值优先级（三层）

1. `modelOptions[modelId][key]` —— 用户在该模型上显式改过的值
2. `options[key]` —— 服务商级设置，但**必须通过当前模型的兼容性校验**
3. `spec.default` —— 模型自己的默认值（可含模型级覆盖）

不预先把默认值写进服务商级配置，否则「没动过」与「显式设成默认值」无法区分，
后续切换模型会带出不该带的参数。

### 兼容性回落

服务商级默认值可能对某个模型非法（例如某服务商默认 `1024x1536`，而该服务商的 pro 模型
只接受 `1024x1024` / `2048x2048`）。取值时做兼容性判断，不合法就回落到模型默认值，
而不是把非法值塞进请求等接口报错。

### 迁移

旧版配置是「每模块一个扁平对象」，新版是「服务商桶 + 模型级覆盖」。升级时把旧对象里的
地址、模型、参数搬到对应服务商的桶里，并写入 `vendorsManaged` 标记，让「与预设不一致就
重置」的老逻辑不再生效——否则用户自己填的代理地址会在重启后被抹掉。

## 4. 密钥与请求路径

- Key 只存本机，不进仓库（`.gitignore` 明确排除），界面只显示"是否已配置"，不回显明文。
- 所有出站请求经本地代理转发：代理维护出站域名白名单，拒绝内网地址（防 SSRF），
  不记录请求正文，日志只记状态码与耗时。

## 5. 出处校验

```
33 个源文件 ──▶ 逐文件 SHA-256 ──▶ 规范化 JSON ──▶ SHA-256 ──▶ RSA-2048 私钥签名
                                                              │
启动时：重算清单 ──▶ 与签名清单比对 ──▶ 用仓库内公钥验签 ──▶ 不符则点名并拦截
```

私钥保存在用户目录（`~/.xinghe/`），不随仓库分发。因此「改文件后自己重新签名」这条路走不通：
伪造的签名用仓库公钥验不过。改过文件但未重签，启动会列出被改的文件名。

## 6. 为什么没有前端框架

界面是原生 JS + CSS 变量主题，无构建步骤。原因：这个工具要能在 `file://`、本地服务、
内嵌浏览器三种环境下一致运行，用户（剪辑师、编剧）不该为了改个文案去装 Node 工具链。
代价是状态管理要自己写清楚，所以状态集中在单一 `state` 对象 + 显式 `persist()`，不做隐式双向绑定。
