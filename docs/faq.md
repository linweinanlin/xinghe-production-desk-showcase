# 常见问题

## 为什么公开仓库里没有源代码？

因为这是一个展示仓，用来放项目介绍、截图与技术文档。源码在私有仓库：

`github.com/linweinanlin/xinghe-production-desk`（未公开）

GitHub 的公开仓库无法只公开一部分代码——只要推上去，所有人都能完整查看、克隆、fork。
所以「公开可见、源码不公开」只能靠**两个仓库**实现：公开仓放说明与截图，私有仓放代码。
私有仓的链接对没有权限的人返回 404，但链接本身写在 README 里，方便你知道它存在并申请访问。

## 那 HR / 面试官能看到什么？

- 这个页面的功能说明、界面截图、技术架构文档
- 提交频率、语言构成等仓库统计
- 需要看代码时，通过 README 里的联系方式申请只读权限或约线上演示

## 能不能放一小部分代码，证明我能写？

可以，但要注意两点：片段容易脱离上下文、也容易被误读为「只会这一块」。如果要做，建议放
一个**自包含、能跑**的最小示例（例如 schema 生成器的输入输出、参数取值优先级的一个纯函数 +
它的测试），而不是贴几十行散装代码。

本仓当前没有放代码片段，是为了避免出现「仓库里有代码但不能运行」的半成品观感。

## 项目是独立开发的吗？

不是。原版是 MIT 许可的开源项目（AI Drama Pipeline），本项目是在其基础上做的二次开发与重构。
上游归属写在 [NOTICE](../NOTICE) 里，README 也单列了一节说明哪些是我做的。

这一点不建议含糊：作品集里最容易被追问的就是「这块是你写的吗」，如实说明反而加分，
写错一次被查出来，整份简历的可信度都会受影响。

## 上游是 MIT，为什么你的新增部分不直接开源？

选择是「源码可见 + 需授权」：个人学习、自己用、看代码都没问题，复制改名再发布、商用、
提供在线服务需要书面许可。这是作者对自己新增部分的选择权（MIT 只约束上游那部分，
不约束新增部分）。如果你想基于它做产品，可以联系作者谈授权。

## 截图里的项目内容是真实的吗？

是真实使用产生的界面，包含作者自己的短剧项目与其生成的画面。截图未做美化或拼贴。

## 为什么界面是原生 JS，不用 React/Vue？

这个工具要在 `file://`、本地服务、桌面内嵌浏览器三种环境下表现一致，且用户（编剧、剪辑）
不该为了改文案去装前端工具链。代价是状态管理要自己写清楚：单一 `state` + 显式持久化，
不做隐式双向绑定。

## 能提供安装包或试用吗？

可以谈。当前版本依赖本机 Python 环境与 FFmpeg，直接发安装包需要处理打包、Qt 的 LGPL 合规、
以及各模型服务的密钥配置，这些属于交付工程，不在这个展示仓范围内。
