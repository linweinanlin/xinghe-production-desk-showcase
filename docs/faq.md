# 常见问题

## 为什么公开仓库里没有源代码？

因为这是一个展示仓，用来放项目介绍、截图与技术文档。源码在私有仓库：

`github.com/linweinanlin/xinghe-production-desk`（未公开）

GitHub 的公开仓库无法只公开一部分代码——只要推上去，所有人都能完整查看、克隆、fork。
所以「公开可见、源码不公开」只能靠**两个仓库**实现：公开仓放说明与截图，私有仓放代码。
私有仓的链接对没有权限的人返回 404，但链接本身写在 README 里，方便你知道它存在并申请访问。

## 为什么没有上线？它本来就是本机应用

星河制片台是 PySide6 桌面外壳 + 只监听 `127.0.0.1` 的本机服务。使用者自己填各家模型服务的
API Key，所有出站请求经本地代理转发，密钥不出本机；剧本、素材、项目与成片也全部落在本机
工作区。

这不是「还没来得及部署」，而是**形态选择**：一个替创作者调用付费模型、处理未发表剧本和
素材的工具，把密钥与素材交给服务端会引入额外的信任与成本问题。所以它没有公网地址，交付
方式是「可复现的运行包 + 本机运行」，而不是一个网站。相应地，它也不以并发、可用性、
在线监控这类指标来衡量。

被问到「如果让你上线怎么做」时，可以讲清从当前形态到公开分发要补的四件事：白名单打包
（排除密钥、备份、缓存与虚拟环境）、重签出处清单（打成单文件可执行程序会让逐文件校验
失效，需要另做一套针对包内资源的签名机制）、公开下载渠道（私有仓库的 Release 对无权限
者不可见）、以及用户侧环境说明。这些是交付工程，不是架构缺口。

## 能不能放一小部分代码，证明我能写？

可以，但要注意两点：片段容易脱离上下文、也容易被误读为「只会这一块」。如果要做，建议放
一个**自包含、能跑**的最小示例（例如 schema 生成器的输入输出、参数取值优先级的一个纯函数 +
它的测试），而不是贴几十行散装代码。

本仓当前没有放代码片段，是为了避免出现「仓库里有代码但不能运行」的半成品观感。

## 这个项目和上游是什么关系？

本项目基于 MIT 许可的上游项目 AI Drama Pipeline 二次开发，上游归属写在 [NOTICE](../NOTICE)，
README 单列一节说明我主导的部分。两级权属是分开的：上游文件（`web/` 前端、
`director_server.py`、`post_production.py` 等）仍按 MIT，唯一义务是保留版权声明与
MIT 许可全文；四级配置架构、桌面外壳、出处校验、迁移工具、交付链路改造等新增与
修改部分，版权归本人所有，另以源码可见许可发布（复制、改名分发、商用与再分发
需书面许可）。MIT 不要求新增部分开源、不要求沿用 MIT、也不限制闭源或商用。

这一点不建议含糊：作品集里最容易被追问的就是「这块是你写的吗」，如实说明反而加分。
改动**权属口径**过不了证据这一关——初始提交就带有 MIT 全文与 NOTICE，文件头、
README、公开展示仓和简历都记录了来源；把来源说明放在合适位置、把贡献写在前面，
属于表述方式调整，不改变任何权属与许可义务。

## 怎么验证这不是一个 Demo？

不依赖公网链接，可以当场核验：

- **能跑通**：本机准备好 Python 3.9–3.12 与 FFmpeg 后按 README 启动，界面与本地服务可用。
- **有真实产物**：用真实模型服务生成并合成过 12 镜、60 秒的竖屏成片（H.264 / AAC），
  交付中心可导出 SRT 字幕、分镜 CSV、EDL 与剪映草稿；截图来自这些真实运行界面。
- **能复现构建**：仓库内置 SHA-256 清单 + RSA 签名，启动时校验源文件；当场运行校验
  即可得到当前构建指纹，改动任何受清单约束的文件都会被点名。
- **有测试**：`python -m unittest discover -s tests` 可当场跑；界面另有浏览器点击探针。
- **有排错记录**：项目内维护 bug 台账，每条含现象、取证路径、根因、修复与复查结果。
  例如「成片效果差」那次先核对文件容器与编码，发现低码率预览被误当成交付原片，
  再逐帧比对素材，而不是先怀疑合成滤镜。
- **代码可核验**：展示仓只放文档，源码在私有仓，可申请只读权限或约线上演示。

其中「有没有第二个人实际用过」目前是空白，这一点如实说明，不拿自用数据冒充用户量。

## 为什么界面是原生 JS，不用 React/Vue？

这个工具要在 `file://`、本地服务、桌面内嵌浏览器三种环境下表现一致，且用户（编剧、剪辑）
不该为了改文案去装前端工具链。代价是状态管理要自己写清楚：单一 `state` + 显式持久化，
不做隐式双向绑定。

## 能提供安装包或试用吗？

可以谈。当前提供的是**源码分发包**（白名单打包，排除密钥、备份、缓存与虚拟环境；解压后
可当场跑出处校验），运行需要本机 Python 3.9–3.12 与 FFmpeg，模型服务的 API Key 由使用者
自备。

单文件可执行程序暂不提供：现有出处校验依赖磁盘上的源文件清单，打包成单文件后校验会失效，
需要另做一套针对包内资源的签名机制；此外还要处理 Qt 的 LGPL 合规。这些属于交付工程，
不在这个展示仓范围内。
